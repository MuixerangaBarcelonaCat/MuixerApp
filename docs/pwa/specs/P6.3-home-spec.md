# P6.3 — Home (`/home`) Implementation Spec

> **Status:** Approved  
> **Date:** 2026-07-06  
> **Scope:** Refactor Home page to match PWA_SPEC.md section 6.3  
> **Dependencies:** P6.2 (Events + Attendance) — ✅ Completed

---

## 1. Objective

Refactor the existing Home component to show exactly **one card per event type** (the closest upcoming rehearsal + the closest upcoming performance), add an avatar placeholder with the user's initial, and integrate pull-to-refresh.

**Key requirement:** The home page must display the **next** event of each type — the one closest in time.

## 3. Data Flow

```
HomeComponent.ngOnInit()
  └── HomeService.loadHomeData()
        ├── EventService.findAll({ timeFilter: 'upcoming', type: ASSAIG, limit: 1 })
        └── EventService.findAll({ timeFilter: 'upcoming', type: ACTUACIO, limit: 1 })
        → { nextRehearsal: MeEvent | null, nextPerformance: MeEvent | null }
```

Backend unchanged — reuses existing `GET /me/events?type=X&timeFilter=upcoming&limit=1`.

---

## 4. HomeService Interface

```typescript
export interface HomeData {
  nextRehearsal: MeEvent | null;
  nextPerformance: MeEvent | null;
}
```

Returns `null` when no upcoming event of that type exists.

---

## 5. HomeComponent Signals

```typescript
// State
isLoading = signal(true);
nextRehearsal = signal<MeEvent | null>(null);
nextPerformance = signal<MeEvent | null>(null);

// Derived
greeting = computed(() => ...);         // "Hola, {alias|name}!"
avatarInitial = computed(() => ...);    // First letter uppercase
hasEvents = computed(() => nextRehearsal() !== null || nextPerformance() !== null);
```

---

## 6. Template Layout (top-to-bottom)

1. **Greeting header:** Avatar circle (40px, `bg-primary/10 text-primary`, initial) + "Hola, {name}!"
2. **Pull-to-refresh wrapper** (wraps content below)
3. **Loading state:** 2 skeleton cards
4. **Content:**
   - If `nextRehearsal`: section label "Pròxim assaig" + `<app-event-card>`
   - If `nextPerformance`: section label "Pròxima actuació" + `<app-event-card>`
5. **Empty state:** "No hi ha events propers programats." with calendar icon

---

## 7. Avatar Component (inline)

Circle 40×40px in the greeting header row:
- Background: `bg-primary/10`
- Text: `text-primary font-semibold text-lg`
- Content: first letter of `person.alias || person.name` uppercased
- Fallback (no person): lucide `User` icon

---

## 8. Pull-to-Refresh

Uses existing `PullToRefreshComponent`. On refresh:
1. Calls `reload()` method on component
2. `reload()` re-triggers `homeService.loadHomeData()` subscription
3. Signals update when response arrives

---

## 9. Testing Plan

### HomeService (4 tests)
- Returns next rehearsal + next performance (happy path)
- Returns null for missing event type
- Returns null for both when no upcoming events
- Handles API error gracefully (returns nulls)

### HomeComponent (8 tests)
- Displays greeting with alias
- Displays greeting fallback when no person
- Shows avatar with correct initial
- Shows rehearsal card when available
- Shows performance card when available
- Shows empty state when no events
- Shows skeleton during loading
- Pull-to-refresh triggers reload

---

## 10. Decisions Log

| Decision | Rationale |
|----------|-----------|
| `limit: 1` over dedicated endpoint | Reuses existing infra, 2 parallel requests are fast enough |
| Singular signals over arrays | Matches spec (1 card/type) and simplifies template |
| Avatar inline (not separate component) | Too simple for extraction (1 div + 1 computed) |
| No alert banner placeholder | YAGNI — P7 will add it when needed |
| No person selector | P6.4 scope — will be added later |

---

## 11. Out of Scope

- Alert banner (P7)
- Person selector / family management (P6.4)
- Event detail enhancements (separate P6.3 event-detail task)
- Map link icons (already in EventCardComponent if `locationUrl` exists)
